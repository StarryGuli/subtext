# 教练设计

教练是言外的全部。一个窗口、三种模式、一个后端抽象。

## 模式

| 模式 | 输入 | 输出 |
|---|---|---|
| 读 Decode | 收到的英文 | 情境一句话 → **逐句**（原句、中文、就地提示）→ ≤2 个套话 / 文化点 → 一句话语气与潜台词 |
| 写 Compose | 中文或中英混写 | 按语境选的 1–2 个英文（标推荐），「为什么这样说」，直译陷阱 |
| 改 Edit | 自己写的英文 | 修正版、中文意思、≤3 条改动、保留的好处、更地道的说法 |

模式由用户在窗口里手动选。读 → 写之间会带「对方刚发来的消息」（30 分钟内）让回复接上语气。

## 从真实使用里得出的原则

来自 166 轮真实聊天的复盘（2026-10-12 至 11-13）：

1. **读默认逐句。** 贴来的消息常是好几句、满是缩写；只给「值得学的几点」会被追问「逐句」。逐句是主体，教学点退到次要。
2. **不在结尾提问、不推销下一步。** 回复结尾的「要不要我再讲……」从来没被接过。
3. **看不到上文就直说是推测**，不编。
4. **单个词的问题只答那个词。**
5. **语音输入的同音词错误是噪音，改掉不评论。**
6. **聊天体不当错**：全小写、`u`、`tho` 是语域，不是错误。
7. **模式不猜。** 把中文当成别人发来的、把解释当成要组句，都曾让一轮白费。

## 闸门

只处理用户亲手提交的文字。拦下：空、超长（`max_chars`）、疑似密钥或密码、链接与代码。
