# 教练模式设计

教练是输入法的一个能力，不是单独的 App。两个触发场景，一个后端抽象。

## 触发

| 场景 | 触发条件 | 模式 | 输出 |
|---|---|---|---|
| 解码 | 剪贴板出现新的英文文本（检测到一次新的复制） | Decode | 情境一句话 → 2–5 个教学点 → 语气与潜台词 → 一个引导问题；译文默认折叠 |
| 组句 | 在中文输入状态下上屏或停顿一句话 | Compose | 按语境选的英文（语气档位、是否缩写），加「为什么这样说」 |
| 改稿 | 英文模式下写完一句自己的草稿 | Edit | 修正版在前，逐条说明；不把刻意的风格选择当错 |

语气与缩写由上下文决定：当前应用（邮件 / 聊天 / GitHub）、最近输入、剪贴板里对方的语气。拿不准且影响很大时才问，一次最多一个问题。

沿用 `english-message-coach` Skill 的硬规则：先答完再说别的、不用问句填内容、不重复问、不复述不感慨；说「看不懂」或「直接说」立刻给直白版本。

## 隐私与边界

剪贴板和输入内容会发给后端，所以：

- 只处理**新复制**且判定为英文的文本，长度设上限。
- 跳过密码管理器等标记为隐蔽（concealed / transient）的剪贴板内容，跳过 Secure Input 状态，跳过按应用关闭名单里的应用。
- 云端后端（OpenAI 兼容、Anthropic）首次启用要明确提示数据去向；本机 CLI 后端数据只经过用户自己的账号。
- 默认关闭，用户选定后端后才启用。

## 后端抽象

新增 crate `subtext-coach`（平台无关，遵守 Core 不依赖平台 API 的约束）：

```text
CoachBackend (trait)
├── ClaudeCli     本机 `claude -p`，走订阅额度
├── CodexCli      本机 `codex`
├── OpenAiCompat  复用 qingjian-predict 的聊天客户端
└── Anthropic     Messages API
```

请求在独立线程里发，「最新请求优先」，结果带序号，过期丢弃，永远不阻塞输入（沿用 `qingjian-predict` 的做法）。

## 面板

形态以 [coach-mockups.html](coach-mockups.html) 为准：短内容用跟光标的注释卡，需要深聊时展开成侧栏。配色沿用主题色板（正文、译文、生词橙、云联想青、鼠尾草绿高亮），辅助信息始终弱于正文。
